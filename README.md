# 🛡️ 灾害应急指挥与救援资源调度平台

基于 **Vue 3 + Vite + 高德地图 JS API v2.0** 的应急指挥演示系统。

## 功能特性

- **高德地图核心交互**
  - 受灾范围叠加（`Polygon`）、事件覆盖物（`Marker` 脉冲气泡）、人口密度热力图层（`Heatmap`）
  - 多类事件（洪涝/地震/火灾/山体滑坡/台风）按严重等级区分样式
  - 内建地图控件（缩放/比例尺/鹰眼）
- **事件管理**：搜索、类型/等级/状态筛选、事件详情、处置状态流转、处置时间线
- **资源调度**：多个资源库/救援点库存，拖拽式派发物资到受灾点，自动在地图绘制派发路线、估算距离与到达时间（直线 × 路网折算的演示算法）
- **物资派发闭环**
  - 分批签收：现场可多次签收，记录签收回执（数量/签收人/时间），在途量随每批签收逐次递减
  - 数量分账：每条派发独立核算 在途 / 实收 / 短缺 / 退回 四本账，需求清单按「实收+在途」计保障量、按实收单独回写
  - 短缺补派：签收时可同批认定短缺，缺口自动重新释放；一键按短缺量就近补派（库存不足跨基地拆单），补派单回链原单并防重复补派
  - 退回入库：在途余量可分批原路退回、库存回补，不再计入保障量；超量签收/退回与已办结记录的重复操作一律拦截
  - 撤回留账：撤回不再删除派发记录，在途（或挂起待续派）余量原路回库，已发生的签收/短缺认定/补派/退回回执与实收账目全部保留；撤回的短缺补派单会冲回原单已补派量、缺口重新释放；撤回单标记为「已撤回」退出保障量、道路阻断评估与地图路线，且不可再签收/退回/补派
  - 全程联动：灾点需求条与统筹缺口实时重算、安置点补给按在途/实收分账核算、道路阻断仅评估在途余量（部分签收后挂起/改派只动在途部分）、地图办结撤线、大屏新增「今日签收 / 短缺待补」
  - 向后兼容：无闭环字段的历史派发记录按全量在途处理，可直接进入新闭环流程
- **安置点按日补给**
  - 按实际入住时段核算：以「补给结算日」为周期，按各成员当日入住/转出时刻折算人日（如 08:00 入住计 2/3 人日），本日消耗 = 人日 × 人均系数实时滚动
  - 耐用品与消耗品分账：消耗品（食品/饮用水/医疗）按日消耗逐日累计；耐用品（帐篷）按在住峰值一次性配备、留在安置点周转，人员转出不回溯、不按日耗
  - 跨日结转：「日结」将当日消耗入账，结余库存（实收 − 已耗）与在途物资自动滚存至次日，日结记录（人日/日终在住/消耗/结转快照）全程留痕
  - 缺口联动重算：人员转出、分批签收、短缺补派、退回/撤回均同步重算缺口（缺口 = 累计需求 − 实收 − 在途），历史欠账跨日滚存
  - 避免重复补给：无闭环字段的历史派发记录按全量在途计入保障量，一键补给仅按当日核算缺口调拨，缺口平后自动拦截
- **多灾点资源统筹 · 协同编制**
  - 多名调度员共同编制：调度员身份切换（赵/钱/孙调度），方案项带编制人标记，同一会话内多人加项/改量/换基地实时可见
  - 库存即时预占：每个方案项生成即按「实物库存 − 他人已预占」预占（不扣实物），可用量实时核减；预占不足的缺口挂账，提交时冲突重算
  - 预占超时释放：预占有 TTL（默认 5 分钟），超时自动落账释放、方案项标记失效，可单项或一键重新预占；失效项提交一律拦截
  - 冲突重算：提交瞬间按最新库存快照，预占池/自由库存池隔离锁定（已预占不挤占自由分配），本基地不足按运输时长跨基地重分配，仍不足如实反馈
  - 原子提交：超时清理 → 统一校验 → 预占核销锁定 → 批量派发一次性生效，无中间态；会话回链全部派发 id
  - 撤销归还：编辑态撤销归还全部预占、作废方案；已提交撤销把整批派发作撤回（在途余量回库、签收/短缺账目留档）
  - 方案版本全程留痕：建会/编制/超时/提交/撤销逐次自增版本号，纳入分支回放（seek 精确还原方案项、预占台账、会话状态、版本号）
  - 库存变动流水：派发/补派/补给/签收/退回/挂起/续派/改派/撤回/抢修派工结算/转移车辆占用等实际出入库逐笔入账（预占不入流水），帧差异「资源占用」维度逐笔展示
  - 向后兼容：无协同字段的旧方案项按旧口径提交时自动补预占；旧快照无协同字段时归一化为空态
  - 提交时统一校验并锁定库存，库存冲突自动按运输时长重新分配，仍不足的缺口如实反馈
  - 批量派发联动更新事件状态与时间线、地图路线、大屏统计；需求清单实时显示 已派/需求 进度
- **群众转移安置**
  - 围绕灾情事件建立转移批次，指挥员分配车辆（占用资源库车辆库存）与安置点（预占床位）
  - 现场三环节登记：接运 → 入住 → 转出，支持单人（姓名/证件号）与批量两种模式
  - 重复登记检测：本批次重复直接拦截；跨批次重复可一键「改派」人员；批次级支持改派安置点/车辆
  - 床位容量联动：入住校验剩余床位（本批次预占自动释放），超容量提示改派
  - 未完成批次按人员分组拆分：勾选成员（在途/在住，已转出不参与）携带全部登记历史（接运/入住/转出时间戳）拆为独立批次；新分组可分别安排车辆（从基地库存新占，原批车辆保留）与安置点（含已入住成员锁定原安置点，跨点按剩余床位校验），计划人数随人切分
  - 拆分联动：床位预占按各批未入住名额重分配、新分组运输路线独立重算 ETA 并即时纳入生效阻断评估（绕行/改派/挂起）；两批按各自登记进度重新推导状态与办结条件（满员全转出仍自动办结回收车辆）；事件转移进度与指挥大屏按人汇总守恒，操作留痕事件时间线，新批次带 `splitFrom` 溯源
  - 安置点物资按日补给核算（人日折算 + 耐用品/消耗品分账 + 跨日结转），一键按当日缺口就近调拨（生成补给派发记录）
  - 全部转出自动办结并回收车辆；进度实时回写事件详情、处置时间线与指挥大屏统计
- **道路阻断处置**
  - 现场人员上报封闭范围：地图圈画多边形（单击标点、右键/双击完成）或一键「快捷上报」当前事件运输走廊
  - 影响评估：自动检出路线穿越封闭区（含与封闭区边界共线/贴边行走）的在途物资派发与转移批次，指挥员勾选确认
  - 方案生成：逐条给出 联合绕行（多处生效阻断一次绕清，含里程/时长增量）→ 改派（换基地/换安置点，自动避开全部生效阻断）→ 挂起 候选，可逐条调整、一键执行
  - 执行前复核：执行瞬间按最新库存/床位与全部生效阻断重新校验；原方案失效（库存被占用、新阻断封堵走廊）时自动降级为绕行→改派→挂起
  - 跨阻断联动：一处处置（绕行/改派/挂起）后，其它生效阻断上的同一任务自动销项或重开待处置；新建派发/批次即时纳入评估
  - 执行同步：地图路线（绕行途经点）、到达时间（ETA 重算）、车辆与床位占用（改派联动释放/预占）实时更新
  - 无路可走（目的地/出发地落入封闭区）时挂起任务：派发物资退回基地、不计入已满足量；批次保留车辆床位预占并暂停登记
  - 恢复通行后：绕行路线在剩余生效阻断视角下联合重排（能回直则回直，仍需绕行则重排），挂起任务一键续派（续派前复核路线与库存，仍受其它阻断影响的保持挂起）
- **道路抢修工单闭环**
  - 由阻断记录发起抢修：指挥员从资源基地分配抢修队伍（人员）、车辆与物资，派单即扣减库存；同一阻断只允许一张在途工单
  - 现场接单并上报进度：进度单调递增，可多次延期（阻断继续保留）
  - 完工上报实际消耗：进度须先达 100%（提前完工一律拦截，不登记消耗）；完工后道路仍封闭、进入待验收；验收通过才解除封闭，并在剩余生效阻断视角下重算全部受影响运输（绕行回直/重排、ETA 重算、挂起任务保持不变）
  - 延期或失败保留阻断：抢修失败 / 验收不通过均不解除封闭，可对同一阻断重新派单
  - 撤单与完工按实际消耗归还：撤单、失败、办结统一结算「派单量 − 实际消耗」的剩余人员/车辆/物资回库，结算幂等
  - 强制恢复联动：指挥员直接恢复通行时，抢修中的工单自动撤单、待验收工单视同验收通过办结；地图阻断标记实时显示抢修状态与进度
- **实时预警协同**
  - 气象/地质数据接入：雨量/水位/风速与边坡位移/土壤含水/微震监测站按场景挂载，支持「监测模拟」自动走数与手动注入读数；地图监测站标记随超阈等级着色脉冲
  - 阈值评估自动发布：读数越过 黄/橙/红 阈值自动建单，持续恶化自动升级并补发角色、回落至阈值以下自动解除；同一监测点同时只存在一张生效预警单
  - 多角色告警：按等级扇出通知（值班长/调度员/现场队伍/指挥长/专家组/安置点联络员），逐角色签收或一键全员确认，升级后新增角色需重新签收
  - 确认/升级/撤销/解除闭环：全员确认转响应态；升级抬等级补通知；撤销留痕（误报原因）；全部终态操作幂等拦截
  - 回写联动：预警全生命周期写入事件时间线；事件严重等级随生效预警抬升/回落；确认后事件状态自动推进（已上报→研判中）；红色预警确认按需求缺口自动联动出库（来源「预警联动」，可跨基地拆单），也可对任意生效预警手动执行调度建议；大屏新增「预警中 / 待确认 / 监测异常」实时统计
- **移动端现场协同闭环**（`/mobile.html` + 现场同步微服务，事件溯源）
  - 离线接收预警：联网时拉取离线包（生效预警与逐角色签收状态、在途签收单、抢修工单、生效阻断），断网期间照常查看；预警签收/升级重签/撤销解除全程回写事件时间线与灾情等级
  - 离线作业队列：现场队伍可离线 签收预警、上报位置轨迹、上报道路变化（新封闭/恢复通行/路况备注）、分批签收物资、抢修接单/进度/延期/完工；每条动作本地生成稳定 ID 与 HLC 入队
  - **离线作业分支协同**：现场队伍可切换推演分支开展离线作业；离线包、动作与回执按「推演 + 分支 + 队伍」隔离，动作入队即钉住当时分支、补传固定回原分支；切换期间在途请求单在途去重、回执按 ID 归账不错记，冲突修正后重提仍回原分支；旧版无分支维度队列自动迁移（历史动作归入主干）
  - 联网因果补传：按 HLC 因果顺序逐条应用，复合动作（封闭→自动绕行）经 `after` 拓扑归位；弱网重试/崩溃重放按确定性事件 ID 幂等去重
  - 冲突不阻塞：重复签收/超签/进度回退/非法跳转逐条回执，冲突项留原因可重提或丢弃；并发竞态由 reducer 记冲突账，库存四本账始终守恒
  - 五面回写：预警（签收/升级/终态）、路线（现场封闭自动联合绕行、恢复后回直重排）、库存（签收四本账/抢修按实消耗归还）、工单（接单·进度·验收联动解封）、回放分支（逐帧入轴、seek 还原、分叉隔离）
  - 现场同步服务（:7104）JSONL 离线队列崩溃可恢复；详见 `services/README.md`
- **指挥大屏**：在报事件、等级分布、今日派发、预警协同、道路阻断、抢修中/待验收、在途转移、安置中、受影响群众等实时统计，支持「实时模拟」自动刷新数据
- **历史复盘与节点回放**（事件溯源）
  - 全程留痕：事件流转、物资派发（含签收/补派/退回/撤回/挂起/改派/绕行）、协同统筹方案（建会/编制/预占/超时释放/提交/撤销版本）、群众转移（建批/登记/拆分/改派）、道路阻断（上报/评估/处置/恢复）、抢修工单（派单/进度/验收/结算）每个动作自动沉淀一帧全量态势快照，并汇总该帧新增的事件时间线、阻断处置、抢修工单三类日志；实际出入库逐笔入库存变动流水
  - 按时间回放：时间轴逐节点步进 / 拖动游标 / 1×·2×·4× 自动播放；seek 到任意帧即整体还原当时的事件状态、派发四本账、库存占用与出入库流水、协同方案/预占台账/版本号、床位占用、阻断区与绕行路线，地图路线/阻断区/安置点角标与全部面板同步重绘
  - 四维度复盘详情：🔁状态变化、🗺️路线调整（里程/时长/途经点/基地或安置点变更）、🏗️资源占用（各基地库存与安置点床位增减）、📝处置日志；可按事件/派发/转移/阻断/抢修分类筛选
  - 任意节点分叉恢复演练：从任一历史帧「分叉新分支」继续推演，**原演练分支原样保留不截断**；分支树支持多层分叉与兄弟分支并存
  - 多分支切换推演：随时在各分支末端态势间切换、沿选定分支继续处置；各分支独立维护库存、床位、派发四本账、转移批次、阻断与抢修状态（帧内全量快照天然隔离，互不污染）
  - 分支处置结果对照：任选两条分支（默认当前分支 vs 主干），对齐共同祖先后比对末端态势——事件状态、各基地库存、安置点床位、派发状态/账目、转移批次、阻断、抢修工单逐维度列出差异，并可一键跳到任一分支继续推演
  - 向后兼容：旧版单线 `frames` 历史（含已持久化数据）经 `loadLegacyFrames` 自动归一化为单主干分支，回放/分叉语义不变，首次分叉即升级为分支树
  - 回放只读锁定：复盘期间主工作区业务操作全部拦截并显示只读遮罩，保证历史快照不被污染
- **多灾情场景**：预置多种 mock 场景（典型洪涝、汛期多点并发），一键切换

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 准备高德 key —— 复制样板文件为 .env 并填入自己的 key
copy .env.example .env
#   编辑 .env：
#   VITE_AMAP_KEY=你自己的高德key
#   （可选）VITE_AMAP_SECURITY_CODE=你的jscode安全密钥

# 3. 启动开发服务器
npm run dev
# 指挥端：http://localhost:5173
# 现场移动端：http://localhost:5173/mobile.html （需另起 npm run services 提供网关）

# 4. （可选）启动五微服务后端，移动端经 /sims 代理到推演网关
npm run services
```

> 仓库已通过 `.gitignore` 忽略 `.env`，key 不会进入版本库。`.env.example` 为公开样板。

高德 key 直接写在前端 `.env` 中构建进产物，是**公开可见**的，且有每日调用配额。
- 仅适合本地开发 / 个人演示。
- 部署到生产或公开服务前，请替换为**限定域名**的正式 key，或通过**服务端代理**调用 Web 服务 API。
- 切勿将 `.env` 提交到公开仓库。
